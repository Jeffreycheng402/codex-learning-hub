Beginner Guide

新手入门

Codex 是什么

Codex 不是普通代码补全。它是一种能使用工具的 AI coding agent：可以读文件、编辑、运行命令、检查输出，并在得到新信息后继续调整。

最好的使用方式：让它解释、检查、定位、提出小修改，然后你自己理解、验证并负责最终提交。

Codex vs ChatGPT vs Copilot

  • ChatGPT：更像会讲解的老师，适合解释概念和分析你粘贴的材料。
  • GitHub Copilot：更像 IDE 中的补全助手，强在实时补全和局部建议。
  • Codex：更像进入项目现场的编程搭档，能读项目、改文件、跑测试、总结 diff。

Codex 能帮学生做什么

解释陌生代码 定位 bug 与 compile error 把 rubric 转成 checklist 生成测试用例表 检查 README 与 GitHub PR 准备老师 viva/demo 问题

第一次使用 Codex 的步骤

  1. 选择一个小项目或课堂练习，不要一开始就用整份 assignment。
  2. 提供课程语言、你的水平、项目入口文件和运行方式。
  3. 先要求 Codex 总结项目结构，不允许修改文件。
  4. 让它解释 50-100 行代码，并用一个输入例子 trace 执行过程。
  5. 再让它检查一个小 bug 或一个 rubric 项，要求最小修改建议。
  6. 看 diff、运行测试、自己复述逻辑后再提交。

Workflow

使用流程

ChatGPT 中使用 Codex

适合概念学习、解释代码片段、分析 assignment requirement、生成 prompt、准备答辩问题。把相关文件、错误截图、terminal output 和 rubric 放在同一轮对话里，并说明课程语言和你的水平。

我是一名大学 IT 初学者。请先阅读 assignment requirement 和 rubric，只做检查清单，不要写代码。然后告诉我需要提供哪些文件才能进一步检查。

VS Code 中使用 Codex

适合边写边解释、修复当前文件、检查多个文件关系和 review diff。明确写清“只读/只改当前文件”“禁止重写”“保持 beginner-level style”。

请只检查当前文件是否有明显 bug 和 readability 问题。先列出发现，不要修改。只有我确认后，才给最小 diff。

Terminal / CLI 中使用 Codex

适合在项目根目录让 agent 读文件、编辑、运行 compile/test 命令。先让它确认 repo 结构，再运行安全的测试命令。

请在当前项目中先运行测试并总结结果。不要修改文件。若测试失败，请指出最可能的 3 个原因和下一步验证命令。

GitHub 联动

Codex 可以基于 repo、issue、PR、diff 和测试结果做检查。它适合总结改动、检查 README、生成 PR 描述、review bug 和 missing tests。

请 review 这个 PR。请先列出高风险问题，再列出缺失测试，最后给一个简短 summary。不要讨论风格偏好，除非影响可读性或 requirement。

Codex App 桌面版

适合管理多个项目、查看 diff、使用 worktree、Git 和更长时间的代码任务。把它当作任务控制中心，而不是一次性问答窗口。

Assignment Helper

作业辅助

核心原则

Codex 应该帮助你理解要求、发现问题、学习修复方法，而不是替你完成全部核心工作。课程作业的最终责任永远在你。

提供 requirement

让 Codex 先总结任务目标、输入输出、限制和提交物。不要在它没理解要求时直接要求写代码。

提供 rubric

让 Codex 把 rubric 转成 checklist，并逐项标注已满足、部分满足、未满足或需要确认。

要求最小修改

限定允许修改的文件和范围，写清“不要重写整体结构、不要引入新库、保持我的风格”。

避免 academic misconduct

不要提交自己不能解释的代码；遵守学校 AI 政策；保留自己的草稿、笔记、测试和修改原因。

准备老师可能问的问题

让 Codex 根据你的真实代码生成 viva/demo 问题，覆盖逻辑、边界情况和设计选择。

最终检查

运行测试、看 diff、检查 README、确认没有隐私文件或临时文件，并确保你能解释每处关键修改。

Prompt Library

可复制提示词库

每张卡片都包含标题、使用场景和 prompt 内容。点击“复制”可直接复制，然后把课程语言、文件名、错误输出或 rubric 补充进去。

解释代码 prompt

适合看老师示例、同学项目、旧代码或报错附近代码。

请用初学者能懂的中文解释这段代码。按：整体目的、每个函数、关键变量、执行流程、可能出错点、我应该复习的语法点来讲。不要改代码。

Debug prompt

适合程序结果不对、按钮无效、测试失败。

这是预期结果、实际结果和相关代码。请先列出最可能的 3 个原因，以及每个原因如何验证。不要马上修改。

Compile error prompt

适合 C++、Java、TypeScript 编译失败。

请解释这个 compile error 的真正含义，指出最可能的源代码位置，并给 beginner-friendly 的最小修复。请区分根本错误和连锁错误。

Rubric 检查 prompt

适合提交前对照评分标准自查。

请把这个 rubric 转成 checklist，并用我的代码逐项标注：已满足/部分满足/未满足/需要确认。每个问题给证据文件位置，不要直接帮我写缺失功能。

C++ prompt

适合 C++ assignment、menu、function、file I/O 和 input validation。

请保持 C++ beginner style，只使用我学过的 if/else、loops、functions、arrays/vector、basic file I/O。重点检查 input validation、menu、file I/O 和 edge cases，不要用高级库或 OOP 重构。

Python prompt

适合 Python traceback、数据处理和函数拆分。

请帮我 debug 这个 Python error。先解释 traceback 从下往上怎么看，再说明数据流和变量作用，最后给最小修复建议，保持初学者风格。

HTML/CSS/JavaScript prompt

适合 web assignment 的布局、响应式、无障碍和交互检查。

请检查这个网页 assignment 的 HTML/CSS/JS：layout、responsive、accessibility 和 JS interaction。先列问题和优先级，不要直接改。若需要修改，请只做最小修改。

Cybersecurity lab prompt

适合合法授权实验、靶场或 CTF training 的报告学习。

这是授权 cybersecurity lab 的 terminal output。请解释每条命令和输出代表什么，说明风险等级、证据和防御建议，并帮我写 report 段落。不要提供非法攻击步骤。

GitHub repo review prompt

适合接手 repo、检查 README 或理解项目结构。

请阅读这个 repo 并总结：项目目的、运行方式、主要文件、测试方式、潜在风险。先不要修改。请告诉我应该先看哪些文件。

Pull request review prompt

适合团队项目 merge 前检查。

请 review 这个 PR，优先找 bug、regression、missing tests 和 requirement 不符。按 severity 排序，并给出具体文件位置和可执行建议。

README prompt

适合课程项目、GitHub 提交和团队交付。

请根据项目内容生成 beginner-friendly README：简介、功能、安装、运行、测试、文件结构、已知限制。不要夸大项目功能，所有命令必须来自实际项目配置。

老师提问准备 prompt

适合 demo、口头答辩和代码检查前练习。

请根据我的代码生成 10 个老师可能问的问题，并给简短参考回答，重点包括核心逻辑、边界情况、我为什么这样设计，以及哪些地方我必须能现场解释。

Safety Guide

安全使用指南

为什么要备份

Codex 可能误解 requirement、改到无关文件或引入新 bug。最简单的备份方式是 Git commit，也可以复制一份项目文件夹。

如何看 diff

diff 是修改前后的差异。接受修改前逐文件查看新增、删除、变更行，确认每处都和任务相关。

避免乱改文件

在 prompt 中写清允许查看和修改的文件范围，例如“只允许改 src/input.cpp 和 tests/input_test.cpp”。

保护隐私

不要在包含护照、银行卡、私人照片、密码、API key 的文件夹运行。公开 repo 前检查 `.env` 和临时文件。

避免危险命令

不要让它执行删除大量文件、上传隐私、改系统配置或操作真实攻击目标的命令。看不懂命令先要求解释。

Git / GitHub Basics

Git 与 GitHub 基础

Git本地版本控制工具，记录文件修改历史。
GitHub在线托管 Git repository 的平台，适合备份、协作和 PR。
Commit一次保存点，包含修改内容和说明。
Branch独立开发线，适合尝试功能或修 bug。
Pull Request请求把一个分支的修改合并到另一个分支，并让别人 review。
.gitignore告诉 Git 哪些文件不要追踪，例如 build output、env 和 cache。
我对 Git 不熟。请解释当前 git status 和 git diff，告诉我哪些文件被修改、每个修改可能来自什么任务，以及下一步应该 commit、继续改还是回退。

FAQ

常见问题

Codex 会不会帮我代写？

它有能力生成代码，但你不应该把它当代写机器。更安全的用法是让它解释、检查、debug、给提示和最小修改建议；最终代码必须由你理解、验证并负责。

Codex 和 Copilot 有什么区别？

Copilot 强在 IDE 内实时补全和局部建议；Codex 更偏 agent workflow，可以围绕一个目标读项目、改文件、运行测试并总结结果。

初学者应该先用哪种方式？

先在 ChatGPT/Codex 里解释代码和 assignment requirement，再在 VS Code 中检查当前文件，最后学习 Git diff/commit 和 CLI/Codex App。

Codex 会不会改坏我的代码？

有可能，所以要先备份或 commit，限定修改范围，要求它先分析不修改，并在接受前逐个看 diff、运行测试。

怎么让 Codex 不要写得太高级？

在 prompt 里说明课程范围，例如“只使用 loops、functions、arrays/vector，不要 class、template、lambda 或外部库”，并要求保持你的原始 coding style。

怎么用于 C++ assignment？

让它重点检查 input validation、menu loop、function responsibilities、file I/O、array/vector 越界和 edge cases。不要让它重写整体结构。

怎么用于 cybersecurity lab？

只在授权环境使用。让它解释命令输出、风险等级、证据和修复建议，并明确要求不要提供真实目标利用、凭证窃取或持久化步骤。

Summary

总结与下一步学习建议

Codex 最重要的价值，不是让学生少学代码，而是让学生更快进入真实编程循环：理解需求、阅读代码、定位问题、做小修改、运行测试、看 diff、解释自己的选择。

  1. 拿一个小 assignment 或练习项目，用 Beginner 路线走一遍。
  2. 每次只做一个小目标：解释、debug、检查、测试、总结。
  3. 学会写带背景、目标、范围、限制和输出格式的 prompt。
  4. 每次修改前先 checkpoint，每次修改后看 diff 并运行测试。
  5. 最终原则：先让 Codex 分析，再让它给最小建议，最后由你亲自理解、修改、运行和提交。
